## 范围声明（先于一切）

**本决策仅约束 spec 规范工作流的审查验收环节（Step 10 / ADD 审计报告），不改变金融数学推理框架（sixlayer 代码、六层架构定义、Lean4 验证策略）的任何设计。** 这是流程层约束，不是推理层约束。取证矩阵规范化的对象是"审查如何留痕"，与被审查对象是数学证明还是普通工程代码无关。若未来 sixlayer 的 L5（报告层）想复用该机制，须另立 ADR。

## 背景（Context）

### 触发实例

另一会话的一次 ADD 审计产出了如下形态的取证矩阵（节选）：

| 取证手段 | 覆盖项 | 结果 |
|---|---|---|
| 静态读码（精确行号） | D-A6 校验前置 L79-91、D-B2/B4 窗口操作 L124/L134 | ✅ |
| 运行时脚本取证 | D-A7 maxlen=7、D-B5 转换轮 n==K 逐轮验证 | ✅ |
| git diff 空输出 | D-F1~F5 五项隔离边界 | ✅ |
| pytest 输出 | Q-2/Q-3: 41 项文件级 + 485 全量 | ✅ |
| 盲区扫描 | 25 项断言无恒真式 | **发现 1 项** |

对该实例的六层分析（2026-08-16 会话）得出：每条审查结论绑定"取证手段 × 覆盖项 × 可重放产物"能系统性改善审查效果，但存在需预先封堵的失效通道。

### 本项目反面基线（无证据绑定的失效实证）

| 事件 | 失效模式 | 缺失的证据 |
|------|---------|-----------|
| M6 Step 4/6 并发自查 | review checkbox 与正文同一次 Write 打勾 | 无独立 pass 的执行痕迹 |
| M6 `Decimal.ulp` 事件 | "版本已验证"声明失实（3.12+ API 跑在 3.11） | 未绑定可重放的版本检查命令 |
| M2 §10.1 统计虚报 | 从 pytest 总数推算分项，4 项零测试虚报 7/7 通过 | 无逐项测试名映射 |

### 根因

未绑定证据的审查结论不可证伪：写"✅"成本 O(1)，复核成本 O(n)，成本不对称激励形式化审查。自然语言结论（"我查了"）与可验证工件（"查这个会显示 X"）在文本上不可区分——这是 Popper 可证伪性在流程层的实例。

## 决策（Decision）

Step 10 的 ADD 审计报告增设**取证矩阵**标准节，受以下 5 条规则约束：

### 1. 证据五分类（按可重放性定级）

| 等级 | 类型 | 特性 | 附加约束 |
|------|------|------|---------|
| E1 | 可重放命令（git diff / pytest / --collect-only 输出） | 第三方可原样重放 | 无 |
| E2 | 运行时脚本取证 | 可重跑但**场景自选** | 须附场景选择理由，或包含对抗性场景（边界轮、异常输入），防"场景选择偏差伪装成运行时证据" |
| E3 | 静态读码行号 | 可核对但**随重构腐烂** | 强制绑定 commit hash（`L124@<hash>` 格式） |
| E4 | 盲区扫描 / 判断陈述 | 不可直接重放 | 必须以"发现 N 项"语气报告（零发现须声明扫描范围），不可输出裸✅ |
| E5 | 推测 / 未执行 | 无证据 | **禁止出现在审计结论中**；只能出现在"未覆盖项"清单 |

### 2. 双向映射表

审计项 ↔ 证据必须双向可查：
- **Forward**：每个审计项（D-x / Q-x）至少绑定一条 E1-E4 证据
- **Backward**：每条证据标注其覆盖的审计项集合（RTM backward 语义的审计版，与 ADR-0004 决策 3 同构）

### 3. 诚实结果列（Goodhart 防御）

**约束过程，不约束结论倾向**：
- "发现 N 项"（N≥1）是合法且正常的输出——审计的合法性来自允许发现问题
- **禁止**定额化（"必须发现≥1 项"会制造假问题）
- 零发现不直接判合规，触发**降级重扫**：换证据等级（如 E3 行号 → E2 脚本）或换角度重扫一次，仍零发现方可记合规并声明扫描范围

### 4. 最高等级绑定原则

每个审计项应绑定其**可用的最高可重放等级**证据。绑定 E4 判断陈述而 E1/E2 可得，视为约束的静默降级（伪造成本回归 O(1)，约束失效）。抽查时优先抽查"高等级可得却绑低等级"的行。

### 5. 风险分级执行（成本可控）

五类取证不必每次全量执行：
- **P0 审计项**（不变式、隔离边界、安全相关）：全量执行 + E1/E2 证据
- **其余审计项**：抽查执行，但被抽中时同样受规则 1-4 约束

### 机制原理（为何有效）

当抽查概率 p>0 时，形式化审查（未实际执行而写✅）的期望成本 ≥ p·c(e)，其中 c(e) 为证据重放成本。对 E1 证据，伪造须预生成工件，工件事前成本≈真实执行成本——即**约束将"假装审查"的最低成本抬升至"真实审查"的成本**。此为威慑论证（机制设计常规论证），非已证定理。

### 与 ADR-0004 的关系

本约束是 S1（第二会话复审）的**成本放大器**：取证矩阵给异构复审 agent 提供可抽查的证据基础，把复审从"重读全部代码"降为"抽查证据重放"。两者互补：取证矩阵审"实现 vs 设计"（backward），S1 异构复审补"设计 vs 意图"与同分布盲区——**取证矩阵不可替代 S1**，因其仍由实现侧 agent 执行。

## 考虑的替代方案（Alternatives Considered）

### 替代方案 A: 约束结论倾向——要求每次审计必须发现问题（否决）

- 优点：直接堵"全绿表演"
- 缺点：Goodhart 定额化——agent 会制造假问题或夸大微小问题凑数，审计信号被污染
- 否决理由：M6 元审计的核心教训是"规则本身也可能流于形式"；把结论定额化是把形式主义从"全绿"换成"假发现"，问题更深

### 替代方案 B: 五类取证每次全量强制执行（否决）

- 优点：证据最完整
- 缺点：每个 feature 的审计成本不可持续，约束会被静默放弃（skip-and-forget 的审计版）
- 否决理由：采用风险分级（决策 5）保留约束骨架，P0 全量、其余抽查——与隔离四要素的"降权运行"哲学同构：可见性优先于阻塞性

### 替代方案 C: 不立约束，依赖 ADR-0004 的 S1 异构复审兜底（否决）

- 优点：零文书成本
- 缺点：S1 复审 agent 面对无证据绑定的普通 checklist，只能重读全部代码——成本高且复查的是同一批文本，抽查无抓手
- 否决理由：取证矩阵与 S1 是共生关系（S1 的抽查效率依赖证据绑定）；且 S1 尚在试点（L1 前置条件未满足），当前唯一可立即落地的防线就是证据绑定

### 替代方案 D: 同时推广到 sixlayer L5 报告层与金融数学推理框架（否决/推迟）

- 优点：统一证据规范
- 缺点：六层推理架构的 L5（报告层）输出是定理化叙事（THEOREM/COROLLARY/NARRATIVE 标注体系），其"证据"语义是定理编号引用而非可重放命令——两类证据不可通约，强行统一会扭曲其一
- 否决理由：用户明确范围限定（2026-08-16）：机制设计当前仅围绕 spec 工作流，暂不渗透金融数学推理框架。若 sixlayer 需要，另立 ADR

## 后果（Consequences）

### 正面

- 形式化审查的伪造成本被抬升至真实审查成本（抽查概率 p>0 前提下）
- M2 模式（统计推算虚报）与 M6 模式（并发自查）在证据层被封堵——两者的共同根源是"结论与生成过程解耦"
- S1 异构复审获得可抽查的证据基础，复审成本从 O(全代码) 降至 O(证据重放)
- "发现 N 项"合法化后，审计报告的信息含量上升（问题即产出）

### 负面

- 每个 feature 的审计报告文书成本增加（估计 +0.5-1 小时/feature）
- 行号证据需维护 commit hash 绑定，重构后历史报告的行号失效（hash 可定位历史版本，缓解但不消除）
- E2 场景选择理由引入主观判断空间（通过要求对抗性场景部分缓解）

### 中性 / 需要后续行动

- M7 S1 试点增设**对比臂**：同一 feature 出两版审计报告（证据绑定版 vs 普通 checklist 版），交异构基座复审 agent 抽查，测两类报告的可抽查率与检出率差——数据复用为 ADR-0004 的 L1 前置条件

## 验证（Validation）

### 已有实证（反面基线）

| 依据 | 来源 | 状态 |
|------|------|------|
| 无证据绑定的审查会流于形式（并发自查、统计推算） | M6/M2 元审计实测 | ✅ |
| 触发实例：取证矩阵形态可行且产出了"发现 1 项" | 另一会话 ADD 审计（2026-08-16） | ✅ 单实例 |
| 证据等级与"发现"语气的结构相关性（不可重放证据落于唯一"发现"行） | 对触发实例的 TRACE 分析 | ⚠️ 单实例模式，未统计验证 |

### 待验证项（移交 M7 试点）

- 证据绑定版 vs 普通版审计报告在异构复审下的可抽查率差、检出率差
- 文书成本实测（是否触发"约束被静默放弃"阈值）
- 零发现降级重扫的实际触发频率与二次发现率

### 失效条件（何时重审本 ADR）

- 若 M7 显示证据绑定版与普通版在复审检出率无显著差异 → 降级为可选模板
- 若文书成本导致审计被系统性规避（审计报告缺失率上升）→ 简化为仅 P0 项强制绑定
- 若抽查机制从未实际执行（p=0）→ 威慑失效，整个约束退化为模板 paperwork，须重审执行机制而非规则本身
