## 背景（Context）

### 1. 机制源（已审计 A 类证据）

Cpp_Hub DEVELOPMENT_WORKFLOW v1.1 附录的 discoveries 机制三件（均过差距分析审计）：

- 三态索引 RESOLVED / OPEN / KNOWN【A3】——语义：已有反例+理论解释（可能有论文）/ 已识别裂缝未解决 / 文献有方案但开源库未实现
- 与工作流的集成点："若遇到数值不稳定或边界 case 异常, 不是'修 bug', 而是**记录发现**"【A4】
- 统计与论文转化跟踪：总发现数 / 各态计数 / 潜在论文数【A5】

### 2. Spec_Workflow 缺口（学习回路诊断）

前轮框架学习回路元诊断的 5 项缺失中 4 项与"事故→规则"数据触发腿开环相关：事故依赖会话记忆（无持久载体）、规则无复发数据支撑、无量化跟踪、无论文转化出口。DIS-007 是唯一已工具化的发现（`status: toolized`），但其登记散落在 docs/ 根目录，无索引、无状态词表约束、无新发现入口。

### 3. 首个实测样本（机制必要性的当场验证）

2026-08-17 Tier1 执行中捕获工具层失效：同一文件多个 Edit 并行执行时后发写入以陈旧快照覆盖先发编辑（6/10 位点静默回滚，grep 终验拦截，串行重放修复）。无 discoveries 机制时该事件只会留在会话记忆中衰减——恰是 D5 要封堵的流失模式。登记为 DIS-008（本机制首个新条目）。

## 决策（Decision，accepted 2026-08-17）

**最小版三态发现索引**（吸收机制，不吞并 Cpp_Hub 项目实例）：

1. **载体**: `docs/discoveries/README.md` ——三态索引 + 登记格式；发现正文留在源位置（DIS-007 不迁移，id↔文件名映射登记，沿用 ADR-0006 惯例）
2. **登记字段（固定）**: `{id, 状态, 一句话, 证据锚点, 潜在论文?}`——五字段强制，缺证据锚点不得登记
3. **状态词表**: `open / resolved / toolized`（G2/DC2 词表，与 DIS-007 front-matter 一致；Cpp_Hub 的 KNOWN 态并入 open，加"文献有方案"注记——本仓暂无 KNOWN 型实例，不为空态扩词表）
4. **集成点（2 处，已落 SPEC_PROCESS v1.4）**:
   - Step 2 调研异常 → 记录发现而非"修 bug"
   - Step 10 ADD 审计发现系统性模式（跨 feature/跨仓库复发）→ 记录发现
5. **编号空间**: DIS-001~006 留源项目（[源项目·Cpp_Hub/docs/discoveries/]，PLAN G4 既定）；本仓序列自 DIS-007 起

## 考虑的替代方案（Alternatives Considered）

### 方案 A: 不引入，DIS-007 单例独存（否决）

- 优点: 零新增结构
- 缺点: 学习回路"事故→规则"载体持续缺位——DIS-008 类事件（工具层失效、跨仓复发模式）无登记入口，事故数据依赖会话记忆必然衰减；前轮诊断 5 项缺失中 4 项无法闭环
- 否决理由: 与吸收设计 §5.2 方案 B（零吸收）的否决理由同构——权威源学习通道名存实亡

### 方案 B: 全量复制 Cpp_Hub discoveries 目录（否决）

- 优点: 与源机制完全对齐
- 缺点: 吞并项目实例（001-006 为 Cpp_Hub 数值库特定发现，对本仓无语义）；其"价值"节（差异化招聘信号等）为项目叙事非机制；违反 Tier3 "机制收进来、实例留源头"原则
- 否决理由: 与 Tier3 拒收边界自相矛盾

### 方案 C: 最小版索引 + 双集成点（选择）

- 描述: 如决策节
- 优点: 五字段登记成本 <5 分钟/条；集成点绑定既有步骤（Step 2/10）不新增流程动作；"潜在论文?"字段维持登记动机（Research OS 的裂缝探测器出口）
- 缺点: 僵尸目录风险（登记后无人维护）
- 缓解: 失效条件登记（见下）

## 后果（Consequences）

### 正面

- 学习回路"事故→规则"的持久载体落位；DIS-008 已完成首条实测登记（机制即装即用）
- 与 M7_EVIDENCE_LOG（量化样本）/ DEV-LOG（事件叙事）三分：发现（裂缝本体）/ 账本（审查能力数据）/ 日志（过程记录），查询场景互不重叠
- DIS-007 从孤立文件变为索引条目，"发现→工具化"路径可追溯（007 即 toolized 态的实例）

### 负面

- 新增维护面（README 索引 + 登记纪律）
- 集成点增加 Step 2/10 的执行内容（判定"是否系统性模式"含主观性——缓解: 仅"跨 feature/跨仓库复发"才触发，单发事件不登记）

### 中性 / 后续行动

- DIS-008 状态 open——工具层根因本地不可修（串行编辑纪律 + grep 终验为操作缓解）；若未来工具修复则转 resolved
- 发现统计（Cpp_Hub §5 机制）暂不复制——条目 <10 时索引自明，超过再议（避免过早结构化）
