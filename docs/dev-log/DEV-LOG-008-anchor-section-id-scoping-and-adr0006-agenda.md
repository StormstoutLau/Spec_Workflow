## 决策依据

### ① 为什么是「两处同改收口 + 单一常量」（而非只改一处 / 只补文字）

根因是**同一段硬编码被写了两遍**：`ANCHOR_RE` 尾部与 `_resolve_anchor` 的 § 分支各自写了一遍「`§` 后必须为数字」。只改 J1 ⇒ 同一锚点「门禁放行 / 取证判硬性」**两处结论相反**；只改 J2 ⇒ 取证受理而门禁仍 soft ⇒ 合法锚点被 `step-enforce` **提交阻断**，且 **`J2\J1` 差集由 0 变非空 = 自触发**候选扩权条件（把既有不变量当噪声踩掉）。只补文字（D）则把摩擦原样转嫁给写作者。**选 C 的实质理由** = 抽 `SECTION_ID` 常量后，「两实现漂移」由**待验证的性质**变为**构造上不可违反**（同 B4「唯一实现优于事后对账」、I-10 / A-33 教训）。

### ② 三条口径为什么这样定死

- **字母 + 数字受理**：真实需求在 ADR 层（ADR-0006 九节 `A/B/B2/B3/B4/C/D/E/F` + ADR-0007 五节 `D1~D5`），而 § 形态此前只能退化为**弱锚点** `#L`（`_check_anchor` 只检行数上界、**不检该行内容**）。
- **多字母词形不受理**：`§selftest` 这类是**符号名**而非章节号（受理会把「拼错的章节号」与「单词」并入同一路径，弱化形态守门）；正确写法是单行 `#L`。
- **大小写敏感**：与标题 token **逐字符**一致；`§b4` 不命中标题 `B4`（否则需引入大小写折叠语义，把「机械精确匹配」变成启发式）。

### ③ 定性为真阳性，且**不与 P-061 并条**

工具**正确地拒绝**了一个它不支持的形态（拒绝理由成立、报错可定位）⇒ 按 B18 判别式属「**已被正确拦截**」一侧；P-061 的 `dc_validator` M5 是**假阳性**（把合法链接误判为不可解析）——两者同族比较时必须分列，**不得并条**。

### ④ 存量读数为什么要标「口径」

同族教训（DR-18 / P-050）：**计数声明须附口径与读数日期**——本批的 618 是**存量口径（不含本批 session）**；加入本批 5 条 decision × 2 锚点后现值 628。文档中凡出现该读数处均标注两态，避免「声明 ≠ 重数」。
