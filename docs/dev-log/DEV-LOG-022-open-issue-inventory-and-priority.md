## 决策依据

### ① 为什么优先级表整体刷新 + 原版折叠，而非追加行

原 2026-08-20 版的**裁决对象已全部 done** ⇒ 其矩阵 / 依赖链 / 排序结论**整体过期**，续用即「声明 ≠ 事实」；按本仓既有处置（历史快照折叠、不再维护）**重写整节**，同时**保留仍通用的部件**（评估维度定义 / H 编号命名空间消歧），避免连通用件一起作废。

### ② 为什么判定口径是「触发未满不主动开全套」

本仓核心目标 = 抑制**形式化审查表演** ⇒ 对**触发未满**的观察项，正确处置是「**等触发**」；**触发未满却主动开全套吃狗粮流程 = 表演**。故 P4 项一律标注「❌ 不该」，只对**有交付物、有判据**的批次定「可 / 轻批」。

### ③ 为什么 R-1 判「不需批」

R-1（消费仓 `.gitignore` 忽略 `docs/discoveries/`）的真闭合动作在**消费仓**（**其仓库自治，本仓不代改**）；本仓只留**证据指针**（`downstream_compliance.py` 可机械复核）⇒ 无需为本仓开批。
