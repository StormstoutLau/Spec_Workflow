## 0. 定位与分工（与 FWK-ASSERTION 的关系）

| | [FWK-ASSERTION](ASSERTION_EVIDENCE_FRAMEWORK.md) | 本框架 (FWK-FACT-CHECK) |
|---|---|---|
| 粒度 | **断言级**（A/B/C 三分） | **事实类型级**（数字/日期/归属/本地状态/引用） |
| 回答的问题 | 这条断言**有没有证据** + 推理链**跳没跳步** | 这个证据（事实）**本身是否被写错**（单位/起点/归属/时点） |
| 无法拦截的盲区 | 带链接却单位写错的数字（A 类只要求 URL+引文） | 综合推理跳步（只做事实溯源，不做重推导） |

**分工红线**：断言分级（A/B/C）、B 类推理机械反证、E1-E5 证据分级、审计端不对称配置——这些归 FWK-ASSERTION，本框架不重复。本框架只承接 FWK-ASSERTION "A 类事实"层级以下的**事实内部核查维度**。

**核心原则（继承自源清单）**：一条事实性声明 = 一个可独立证伪的命题。文档可靠性不取决于"写得多详细"，而取决于每条声明的证据强度是否如实标注，以及每个数字/日期/归属是否经得起逐类核查。

## 2. 逐类核查项（本框架核心增量）

> 编号沿用源清单 C1.x/C2.x 的语义，重标为 `FC-#`（Fact-Check），括号内注源编号以便回溯。checklist 的 C1.1"声明清单化"已由 FWK-ASSERTION §7 断言统计表覆盖，**不重复吸收**。

### 2.1 数字类

- [ ] **FC-1 单位核对**（源 C2.2）：数字的单位是否与来源一致（秒 vs 毫秒、GB vs GiB、MB vs GB、请求 vs credits、天 vs 小时）。实例：CDSE `Retry-After` 官方为毫秒，审计文档误写秒。
- [ ] **FC-2 数量级 sanity check**（源 C2.3）：与同类对象横向对比（单文件 1-16 MB vs 官方同类产品 ~40 MB；tile 覆盖数按网格估算）。
- [ ] **FC-3 隐含口径**（源 C2.4）：数字是否绑定了限定条件（"仅 /states/all 端点"、"仅 IAD"、"v2.0 口径"）。范围外推 = 泛化幻觉。
- [ ] **FC-4 数值溯源**（源 C2.1）：每个数字能否指到 L1 来源？指不到的标 `[社区]` 并写明出处。**（此条为 FWK-ASSERTION A 类的数字特化版，保留作核查清单项）**

### 2.2 日期/历史类

- [ ] **FC-5 起点语义**（源 C2.5）："X 年起"的 X 是什么事件？产品首发、首颗卫星、双星组网、数据回补？实例：Sentinel-2 "2017" 实为 2B 双星组网年，数据起点是 2015（2A）。
- [ ] **FC-6 承诺边界**（源 C2.6）：来源承诺的是"从 X 起有数据"还是"从 X 起无缺口"？实例："2012-01-19 起"被加码为"起无缺口"——官方从未承诺无缺口。
- [ ] **FC-7 技术栈时效**（源 C2.7）：架构/组件名是否已被官方改名或迁移（Impala→Trino）。知识截止时间之后的变化必须重新检索确认。

### 2.3 归属类

- [ ] **FC-8 官方 vs 第三方**（源 C2.8）：工具/客户端/MCP/server 是官方出品还是社区产物？"在官方文档里能找到"是唯一判据。实例：gfw-mcp-js 是社区项目，被误当官方能力。
- [ ] **FC-9 承诺主体**（源 C2.9）：某机制（限流、封禁）是官方条款还是社区观察？实例："超限返回 429"（社区观察）vs 官方实际语义"超限临时封密钥"。

### 2.4 本地状态类

- [ ] **FC-10 实测替代记忆**（源 C2.10）：库大小、行数、表存在性，一律以当日实测为准，不以旧会话/旧文档为准；注明查询日期（L3 时效约束）。实例：47.5 GB（旧）→ 46.39 GiB（实测）；"表不存在" → "表存在但 0 行"。
- [ ] **FC-11 存在性 ≠ 非空性**（源 C2.11）：表/文件/目录状态有四档——不存在 / 存在但空 / 存在有数据 / 存在但过期。写文档前确认在哪一档。

### 2.5 引用类

- [ ] **FC-12 链接活性**（源 C2.12）：每条外部引用在审计时点是否仍可访问（404 = 失效）。失效但内容仍有价值者，保留链接加注"审计时已 404"并寻官方侧证。
- [ ] **FC-13 引用支撑度**（源 C2.13）：引用来源真的说了文档声称的事吗？实例：引博客说"三陷阱"，博客本身 404 后该声明证据强度降级为"经验性防御措施"。

### 2.6 一致性与时点

- [ ] **FC-14 交叉一致**（源 C1.2）：同一事实在文档多处出现（总表 vs 正文）时，列出所有出现位置，核查值一致。实例：tile 大小错误在 5.1 总表和 5.2.4 正文各一次，只改一处就留不一致。
- [ ] **FC-15 时点快照**（源 C1.3）：所有"当前状态"类声明标注观察日期（`实测 2026-08-21`）。无日期的状态声明默认过期。

## 3. 幻觉模式库（CHK-H1 ~ CHK-H11）

> 源清单 H1-H11 改名 `CHK-H#`（CHK = 本框架锚），避免撞仓库实例级 H#（LG H1-H7 / dsh H1-H4 / SKL H1-H6，ADR-0007 v1.2）。幻觉不是随机噪声，是可归类的系统性模式：

| # | 模式 | 实例（源清单审计） |
|---|---|---|
| CHK-H1 | 社区口径冒充官方值 | EIA "5,000 请求/小时"（实为 eia-mcp FAQ，官方只说"节流+封密钥"） |
| CHK-H2 | 单位错位 | Retry-After 秒 vs 毫秒 |
| CHK-H3 | 适用范围泛化 | bbox 面积计费仅 /states/all，写成全端点 |
| CHK-H4 | 知识过时 | Impala（已迁 Trino） |
| CHK-H5 | 承诺加码 | "2012 起" → "2012 起无缺口" |
| CHK-H6 | 数量级错误 | tile 1-16 MB vs 实际 ~40 MB |
| CHK-H7 | 归属错误 | 社区 MCP 当官方 |
| CHK-H8 | 本地状态凭记忆 | 47.5 GB / "表不存在"，实测 46.39 GiB / 表存在但空 |
| CHK-H9 | 起点事件混淆 | Sentinel-2 双星年（2017）当数据起点（2015） |
| CHK-H10 | 引用失效未察觉 | 404 博客仍作为"三陷阱"唯一支撑 |
| CHK-H11 | 粒度偷懒 | GFW "2017 起/~5 天延迟"（实为 AIS 2012/96h、SAR 2017/5 天，须拆分） |

**根源共性**：写作者把"检索到的信息"直接当成"验证过的事实"。本框架的全部作用 = 强制在两者之间插入一道可审计的工序。

## 4. 修正处置分级（CHK-R1 ~ CHK-R5）

> 源清单 R1-R5 改名 `CHK-R#`，避开 FWK-ASSERTION §7 报告模板规则 R1-R7 撞名。本分级管**处置**（改什么），FWK-ASSERTION 审计端状态词表管**判定**（对不对）——互补：

| # | 判据 | 处置 |
|---|---|---|
| CHK-R1 硬伤 | 事实错误（数值/单位/起点/归属/适用范围） | 直接改值，保留正确来源 |
| CHK-R2 降级 | 事实方向对但证据强度虚高 | 加档位标注（`[社区]`、"官方未承诺"、"Temporary Boost"） |
| CHK-R3 补注 | 事实对但缺关键限定 | 补适用范围/时点/临时性说明 |
| CHK-R4 失效 | 引用 404 或来源消失 | 保留链接加注失效 + 找侧证或降级 |
| CHK-R5 过期 | 本地状态类与实测不符 | 按当日实测覆盖，标注实测日期 |

## 5. 与 FWK-ASSERTION 错误形态学的映射

本框架的 CHK-H# 与 FWK-ASSERTION §2.1 形态 I/II/III **不是同维分类**，不强行一一映射：

- **形态 I / II / III 按"错误发生的环节"分**：生成期无据 / 弱记忆填充 / 推理跳步。
- **CHK-H# 按"错误的内容类型"分**：单位 / 归属 / 起点 / 承诺 / 本地状态。
- **正交关系**：CHK-H2/H4/H6/H7/H8/H9/H10（凭印象或凭检索信息未验证）是形态 II"弱记忆填充"的内容子类；CHK-H1/H3/H5/H11（检索到真实信息但错误泛化/加码）接近形态 III"综合推理错"的内容子类；形态 I（零命中仍写出）在源清单 18 处修正中未出现——因源清单场景是"有检索但没验证"，非"零命中硬写"。

**实践含义**：形态 III 类错误（推理跳步）仍靠 FWK-ASSERTION §4 B 类机械反证；本框架的逐类核查项（FC-#）与幻觉模式库（CHK-H#）负责在 A 类事实层面把"弱记忆填充"和"过度泛化"提前拦在生成/写入期。

## 6. 快速自检（10 分钟单文档）

> 面向文档发布前或作为下游输入前的快速扫描，粒度比 FWK-ASSERTION §3 自检清单（断言级）更细：

1. 全文搜索所有数字 → 每个能指到 L1 来源吗？单位对吗？（FC-1/FC-4）
2. 全文搜索所有年份/日期 → 起点语义核实了吗？（FC-5/FC-6）
3. 全文搜索"官方/支持/承诺/已存在" → 每处归属核实了吗？（FC-8/FC-9）
4. 引用列表逐个点开 → 都活着吗？（FC-12）
5. 本地状态声明 → 今天实测过吗？（FC-10/FC-11）
6. 同一事实多处出现 → 值一致吗？（FC-14）
