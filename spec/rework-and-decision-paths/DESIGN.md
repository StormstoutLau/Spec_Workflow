## 1. 设计目标

承接 RESEARCH 的 Q1（回写流）/ Q2（多方案·故障链·优先级·顺序依赖·成本收益）/ §3.8（三项候选）结论，本批产出两项交付：

- **交付 A（本批实施）**：让 CHECKLIST 验收统计进入 R7 射程——**先立规范形态（模板），再以与 M4/R7 同构的校验器接管对账**；历史文件不追溯（渐进），新批次起强制。
- **交付 B（本批止于设计规格）**：回写流的实现规格——回写**机械原语已存在**（`spec_runner fork`），缺的是**失效语义**（上游被推翻时无合法状态可标记）。因触及 DC2 状态词表与 front-matter 契约，本批只出规格 + 影响面实测，不实施。

一句话：**A 是「把已存在的纪律（R7）补上缺失的执行位点」，B 是「把已存在的原语（fork）补上缺失的语义」**——两者的共同形态均非「新建系统」，而是**补一个既存机制的空位**。

## 4. 架构设计（交付 A）

### 4.1 落点：扩展 `dc_validator` 的 M4/R7（不新建校验器）

**选择理由**：`dc_validator` 自称「DC 契约校验器（DC1-DC4 **+ R7**）」，其 M4 `check_counting` 已实现「**声明 N 实为 M** → P1」的 R7 同构逻辑，且 hook `files: ^(?!.*\.arc/).*\.md$` **已覆盖 `spec/**/CHECKLIST*.md`**。

⇒ 扩展 M4 为**双分支**（互不干扰）：

```
check_counting(file, text)
  ├─ 分支 ①（既有）：RE_STAT_SECTION 命中 `## 0. 断言统计表` → A/B/H 三类重数
  └─ 分支 ②（新增）：RE_CL_STAT_HEAD / RE_CL_STAT_ANY 命中 `### 10.1 验收统计` → CHECKLIST 表重数
```

**零新增 hook**（复用既有 `dc-validator`）、**零新增脚本**、**零 API 破坏**（分支 ① 逐字保留）。

```
| 类别 | 总数 | 通过 | 失败 | 待办 |

| 功能 | … | | | |
| 接口 | … | | | |
| 不变式 | … | | | |
| 错误处理 | … | | | |
| 性能 | … | | | |
| 兼容性 | … | | | |
| ADD 审计 | … | | | |
| **总计** | N | N | N | N |

```

**规范约束**（三条，本批固化）：
1. **章节号固定** = `### 10.1 验收统计`（禁 §8.1 式漂移、禁标题括注）；
2. **数值单元格 = 纯十进制整数**（禁 `**N + M**` / `N 项 + M 发现` / 括注；加粗 `**N**` 允许）；
3. **表内算术自洽**（两条不变式，见 §8 I-11）：
   - 逐行：`总数 = 通过 + 失败 + 待办`；
   - 总计行 = 8 类行**按列求和**。

> **「条目级重数」的边界（诚实声明）**：本批实现的是**「表内自洽」+「规范形态」**（L1）。真正的**「§10.1 声明数 vs §1-§9 逐项表实际行数」**对账（L2），其前置是**条目标记形态规范化**（现有 `☐/☑/✅/待办/文字` 混用）——登记为 **H-CL2**（§10.2），触发 = 标记规范随模板铺开后。

> **为何异形用 skip 而非 P3**（本设计的一处修正）：`dc_validator.Summary.violations = [r for r in results if r.severity]`——**任何非空 severity（含 P3）都算违规**，与 `repo_stats`「P3 = 信息性非阻断」**语义相反**。故在 `dc_validator` 内使用 P3 会**当场阻断 20/21 历史文件**，与「历史不追溯」直接矛盾。为守住「改动尽量小」，本批**不改 `Summary` 的判定语义**，改用 **`severity=""`（skip 语义）**：既非阻断，又在 stdout 中显式可见（`[skip] <file>: §10.1 形态异形…`）。**P3 语义的全仓统一另立观察项**（`dc_validator` 与 `repo_stats` 的 P3 语义分歧登记，不在本批修）。

## 6. 替代方案

### 6.1 方案 A：模板先行 + 渐进（**选择**）

- 描述：改模板定规范形态；校验器只认规范形态；异形 → skip；历史不追溯。
- 优点：改动面小（模板 1 处 + 校验器 1 分支）；零破坏（20/21 历史文件不阻断）；形态缺口可见（skip 输出行）；与既有「只报偏差」哲学一致。
- 缺点：覆盖仅新批次；L2（条目级真对账）延后。
- **选择理由**：用户裁决；且是唯一同时满足「无破坏」与「缺口可见」的方案。

### 6.2 方案 B：全量标准化（**否决**）

- 描述：一次性把 21 个历史 CHECKLIST 规整到统一 §10.1 表。
- 优点：覆盖最全（R7 无豁免）。
- 否决理由：一次性触及 21 文件 + 5 处散文族改写为表格，**变更面 ∝ 历史包袱**；且与 RESEARCH §6「不引入重型流程」的取向相悖。**降级为后续候选**（若 L2 触发可批量执行）。

### 6.3 方案 C：窄切口（只校验 6 个表格族的算术自洽）（**否决**）

- 描述：不碰模板，只对现有表格族做 `总数 = 通过+失败+待办`。
- 优点：立即可落。
- 否决理由：**不解决「声明无定形」**（新文件仍可任写异形）；覆盖 6/21 且**异形不算违规** ⇒ 校验价值随时间**衰减**（新文件漂移不受约束）。与「模板先行」的因果方向相反（应先定形、再校验）。

### 6.4 方案 D：止于懒加载 gate（**否决**）

- 描述：登记为候选，不实施。
- 否决理由：用户明确选择实施；且**位点空缺是纯机械问题**（无契约变更、无新依赖），不满足懒加载「须有触发条件」的门槛。

### 6.5 落点替代：新脚本 + 新 hook（**否决**）

- 描述：新建 `scripts/checklist_stats.py` + 第 6 个 pre-commit hook。
- 否决理由：`dc_validator` **已自称「+ R7」且已覆盖全 `.md`**；新建会**复制 R7 判定逻辑**（违背 I-10 语义同源，P-047 教训）并新增 hook（`declared.hooks` 5→6 的连带对账）。**R7 的位点应复用其既有宿主**。

### 7.4 裁决点（**v1.5 已裁决并实施**）

- **ADR-0010 三问**（**补论证 B-8**）：
  - **Q1 分层 = Layer-0**：裁决对象是**契约文本的增词**（PLAN §1 DC2 = 纯文档/文件）；`dc_validator` 常量是 Layer-1 **镜像**，按「Layer-1 单向依赖 Layer-0」随契约文本同步 ⇒ **本体判 Layer-0**。（对照：交付 A 的裁决对象是**校验器收录**，本体即 Layer-1 工具行为——两判不同，因**裁决对象**不同。）
  - **Q2 激活条件 = 触发驱动**：一次真实的「上游被推翻且须机械留痕」事例。
  - **Q3 未激活副作用 = 0**：本批零运行时改动（I-15）。
- **DC2 变更流程**：词表为全仓「固定、不得自造」，增词须走契约变更 + Review 裁决 → **v1.5 用户裁决「两项都做」后已执行契约变更**（契约文本 [PLAN §1 DC2](../doc-contract/PLAN.md) + [ADR-0007](../../adr/ADR-0007-unified-document-contract.md) **v1.7** + Layer-1 镜像 `dc_validator` L36）。
- **R2（FTA 判为不可裁 → 回归触发驱动；收敛 B-5）**：`superseded` 是否**同时**覆盖 **CHECKLIST 档**（`pending/accepting/accepted`）与 **`template` 类**（二者共用同一词表副本 `dc_validator` L35/L39）？——**故障链分析呈「对称」（两选项最小割集 3 vs 2 且方向相反），FTA 不产生裁决** ⇒ 依 ADR-0010 **Q2 触发驱动**，等「一次真实的 CHECKLIST / 模板被推翻」事例（详见 §7.6）。
- **R3（FTA 倾向否决；备选保留）**：是否需**显式反向链**（`superseded_by`）？——**故障链分析倾向否决**：反向字段**引入「同一事实两处表达」的一致性失效模式**（`A.superseded_by = B` ∧ `B.upstream ≠ A`，**新增 2 元素割集**），而正向链无此暴露；该结论与 **I-10 的论证结构独立收敛**（详见 §7.6）。
- **与 I-2/I-4 的关系**：默认方案**不新增字段**（DC1 零改动）；不得引入浮点/编码（同 `confidence` 反例，RESEARCH §3.8）。

### 7.5 边界声明（**新增，B-10**）

本规格**只覆盖整体推翻**（上游文档被后继者取代）。**部分推翻**（如仅 RESEARCH §3.8 某候选失效而主体仍有效）**不在射程**——本仓既有处置 = 正文追记 + 修订历史（P-045~P-049 先例）；其机械化未登记为候选，因「部分无效」**缺机械数据源**（不满足 RESEARCH §3.8 的「未表达 ≠ 该表达」判据）。

### 7.6 R2 / R3 的故障链（FTA）判据（**新增 v1.2**）

**动机**：R2 / R3 在 v1.1 中被列为「待裁决」，但**未给裁决方法**。RESEARCH §3.1 Q2 曾把「故障依赖链」列为三项空白之一（社区方法 = **FTA**：自顶事件向下 + AND/OR 逻辑门 → **最小割集**，单元素割集 = 单点故障）。本节即**该方法在本仓的首次真实应用**（登记见 RESEARCH §6）。

**口径固定**（硬前提——不固定则比较的是粒度而非结构）：

| 项 | 取值 |
|---|---|
| 顶事件 T（R2） | 「该被质疑的文档被下游**当作仍然有效**」 |
| 顶事件 T2（R3） | 「返工链**不可追溯**」 |
| 基本事件粒度 | 「一次可观测的判读 / 动作」 |
| 门语义 | 顶事件成立需 **∧**（条件同时满足）；**割集规模 = 条件数**，规模小 = 更易触发 |

**前置机械事实（E1，2026-09-27）**：文档 front-matter `status` 的**语义消费方为零**——唯一读取点 [dc_validator](../../scripts/dc_validator.py) L121-131 只校验「值是否在词表内」、不消费语义；`console_gen` 的 `status` 是 PROGRESS **任务**状态（L136 自注「PROGRESS 原词」）；`upstream` 仅 [downstream_compliance.py](../../scripts/downstream_compliance.py) L181-185 打印为「上游版本」列。⇒ **`superseded` 当前只对人（读者）有意义，对机器无意义**（此事实直接删掉 R2 的一条分支）。

#### R2 两棵树

| 选项 | 失效路径 | 最小割集 |
|---|---|---|
| **不覆盖** CHECKLIST / 模板档 | ① 机械消费方读到作废 CHECKLIST ⇒ **路径不存在**（零消费者）<br>② 人工读者读到 | ②：`a1 有读者` ∧ `a2 无标记` ∧ `a3 无追记` = **3 元素** |
| **覆盖** | ② 消除 `a2` ⇒ 降为 2 元素；**新增** ③ | ③：`a4 有人误标` ∧ `¬a5 无交叉校验` = **2 元素** |

⇒ **两选项割集规模相当、方向相反 = 对称，FTA 不产生裁决。**
**该否定性结论有效**：它排除了「以结构分析强判 R2」这条会产出**假裁决**的路径 ⇒ R2 归 **ADR-0010 Q2 触发驱动**。

| 选项 | 失效路径 | 最小割集 |

| **不设**（仅正向 `upstream`） | T2：`a1 有人查「谁取代了我」` ∧ `a2' 正文未留链` ∧ `a3' 未去检索「upstream 指向本 id」` | **3 元素**；`a3'` 写成检索纪律（grep 级）⇒ **2 元素** |
| **设** `superseded_by` | T2 消除；**新增** T3「链不一致」 | **2 元素**：`a4' 两处之一写错` ∧ `¬a5' 无一致性校验`；欲消 `a5'` 需加校验器 ⇒ **校验器自身成新失效面** |

⇒ **倾向否决**。**交叉验证**：结论与 **I-10 的论证结构独立收敛**——FTA **自下而上**从失效路径推（两处表达 ⇒ 一致性割集），I-10 **自上而下**从「单一实现」原则推（P-047 的 A-33「两实现同错」）；两法同答 ⇒ **互证而非重复**。

#### 方法边界（**必须声明，否则为方法表演**）

1. FTA 给**结构**不给**概率** ⇒ 无法回答「哪个更可能失效」（底事件概率 = E1 不可得）；
2. 结论对**基本事件粒度**敏感（本节已显式固定）；
3. 顶事件定义不同会翻转结论（本节已固定 T / T2）；
4. ⇒ 本分析**只够支撑「结构层裁决」，不足以支撑「优先级 / 成本排序」**。

**推论（登记）**：故障链方法在本仓的角色是 **判据选择器（selection）而非判据生成器（generation）**——对**结构性分叉**（R3）有效、对**触发型决策**（R2）无效。这也解释了 RESEARCH §3.1 Q2 为何把「故障链」列为空白却**不建议立即工具化**。
