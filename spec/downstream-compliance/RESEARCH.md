## 1. 调研目标

**核心问题**（基于 ADR-0006 §C/§D 的决策形态，落地前细化）:

1. **J-1~J-4 的可机械判定形态是什么**——四条判据中哪些是「确定性程序可核」（文件存在 / `git ls-files` / `git rev-list` / `git log --grep`），各自的确切命令与读数语义？
2. **决策 5 的「符合性判定表」在本仓的可落地边界**——哪些部分归本仓（格式 / 生成器），哪些必须归消费仓（表本体 / 裁定）？
3. **ADR-0006 记录的残余状态 R-1/R-2 是否仍然成立**——重审 #1（2026-09-23）的手记读数在 3 天后是否已漂移？

## 3. 调研发现

### 3.1 J-1 指针存在**且已入库**——一条判据含两个可核事实

A-1 副本指针存在：`docs/ASSERTION_EVIDENCE_FRAMEWORK.md` L5 与 `docs/discoveries/007_hallucination_audit_asymmetric_evidence.md` L6 各含一行 `> **⚠️ 权威源已迁移**: 本文件为历史副本，冻结于 v1.1。权威版本 = Spec_Workflow 仓库`【E1】。

A-2 入库状态**分叉**：AEF 副本 `git ls-files -- docs/ASSERTION_EVIDENCE_FRAMEWORK.md` **命中** ⇒ 已入库；DIS-007 副本 `git ls-files` **空** ⇒ 未入库。⇒ **同一批指针，一侧在版本库内、一侧不在**——单看「grep 命中」会把两者判为同一状态（重审 #1 正是如此）。

A-3 未入库的**根因记载需精化**：`git check-ignore -v` 返回 `.gitignore:82:docs/discoveries/`，即被忽略的是**整个目录前缀** `docs/discoveries/`，而**不是**某一具体文件（ADR-0006 §B 原记为「`.gitignore` L82 单文件」）【E2】。⇒ 该目录下**所有**发现副本皆不可入库——影响面比记载更宽。

### 3.2 J-2 提交已推送——「ahead 11」记载已失效

A-4 消费仓与远端**完全同步**：`git -C F:\Cpp_Hub rev-list --left-right --count origin/main...HEAD` 输出 **`0	0`**（左=behind、右=ahead 皆为 0）【E2】。

> **与记载冲突**：ADR-0006 §B/§F 记录「Cpp_Hub `main ahead 11 未推送`」（2026-09-23 手记）。3 天后实测为 `0 0` ⇒ **R-2 消解**。

### 3.3 J-3 版本行一致性——此前**从未测过**，本批给出首组读数

A-6 权威源（本仓）`docs/ASSERTION_EVIDENCE_FRAMEWORK.md` 版本 = **1.4.2**。
A-7 权威源 `docs/007_hallucination_audit_asymmetric_evidence.md` 版本 = **1.3**。
A-8 两副本指针内冻结版本**均为 1.1**（指针文本「冻结于 v1.1」）。

⇒ 差异量：AEF 侧 **1.4.2 − 1.1**、DIS-007 侧 **1.3 − 1.1**。此前无任何机械记录——这正是决策 5「差异须在判定表 C-2 列有记录」要覆盖的缺口。

### 3.4 J-4 回流频度——与重审 #1 一致（0 次、窗口未满）

A-5 窗口（2026-08-17 → 2026-09-26，**40 天**）内：总提交 **39** 条，`--grep` 回流标记（`回流|absorb|absorption`）命中 **0** 条有效回流（唯一命中 `96edc5c` 是**指针提交自身**，非回流内容）【E2】。

> **〔订正（2026-09-29，P-056）〕** 本条读数**不可复算**，两处实现缺陷（详见 [IMPLEMENTATION §3.4](./IMPLEMENTATION.md)）：① `--since` 用**裸日期** → git approxidate 以**当前时钟补齐时刻**，截止点随执行时刻漂移（同一冻结仓实测 09-26 上午 **39** / 09-29 22:10 **36** / 09-29 23:0x **35**）；② `--grep` 缺 `-E` → `|` 为 **BRE 字面量** ⇒ 标记**恒 0**（假阴性）。**钉死时刻** `--since="2026-08-17 00:00:00 +0800"` 的权威读数 = 总 **40** / 标记 **1**（= `96edc5c` 自身）⇒ A-5 的「0 条有效回流」**结论仍成立**（标记 1 全部来自指针提交），但分母由 39 订正为 **40**。

### 3.5 本批核心发现：**手记残余状态自身会漂移**

| 残余 | 重审 #1（2026-09-23 手记） | 本批实测（2026-09-26） | 变化 |
|---|---|---|---|
| R-1 | 「`DIS-007` 指针按 `.gitignore` L82 不入库」 | AEF 侧**已入库**；DIS-007 侧仍未入库，根因 = **整目录**被忽略 | **精化 + 部分解除** |
| R-2 | 「main ahead 11 未推送」 | `0 0` 完全同步 | **消解** |
| — | J-3 未测 | 差异 1.4.2-vs-1.1 / 1.3-vs-1.1 | **首测** |

⇒ **3 天内一处消解、一处根因失真**。这与 ADR-0006 §D 的问题定义完全吻合：三层封堵**全为人工**，其失效是**结构性的**——手记不是「暂时不准」，而是**没有机制保证它准**。

## 4. 综合分析

### 4.1 关键发现总结

1. **J-1~J-4 全部是确定性程序可核的**（文件存在 / `ls-files` / `rev-list` / `log --grep`）——零模糊语义，无需 LLM 判断【置信度: ★★★★★】
2. **「手记残余」是不可靠载体**：3 天两处漂移，且漂移方向不一（一处变好、一处根因失真）【置信度: ★★★★★】
3. **决策 5 的表不能由本仓代持**：表归消费仓是 SLSA 语义的直接映射；本仓能做的只有**格式 + 生成器 + 判据**（§C 已明示「委托须显式」）【置信度: ★★★★☆】
4. **判据应共享同一实现**：J-1 的「指针」与「入库」是两个事实，若拆成两处判定极易退化为单一 grep（重审 #1 的错误形态）【置信度: ★★★★☆】

### 4.2 技术 landscape

既有先例 `independent-verify`（P-025）已把「decision 锚点真实性」机械化为 `verify-anchor`（文件存在 + 章节精确匹配 + 行号上界），验证了「**把审查臂的自报变成可核读数**」这条路线在本仓可行。本 feature 是**同一方法在跨仓对象上的复用**（本仓 → 消费仓）。

### 4.3 研究空白

- 跨仓判据此前**无任何机械载体**（J-1~J-4 只存在于 ADR 文字中，靠人手执行）；
- 「符合性判定表」此前**无格式定义**，故 J-3 的「差异须有记录」不可判——**判据依赖一个不存在的载体**。

## 6. 对设计的输入

### 6.1 可用的技术方案

- 单脚本检查器（`scripts/`，stdlib + `subprocess` 调 `git`），消费仓以**登记表常量**声明；
- `--emit-table` 生成判定表骨架交消费仓落盘（避免本仓代持表本体）。

### 6.2 关键约束

- **零新依赖**（本仓不变式）；
- **不接三校验器**（ADR-0006 §D 明示 J-1~J-4 为「纪律 + 可复算命令」，非门禁）；
- **表归消费仓**（决策 5 归属规则），本仓只读表、不写表；
- 消费仓不可达时应**显式报结构性异常**，不得静默通过。

### 6.3 风险

- 消费仓路径硬编码（`F:\Cpp_Hub`）——跨机不可用，需以「不可达即 exit 2 提示」兜住；
- 判定表缺失时 J-3 无法判「已记录」——须显式标注「待消费仓落盘」而非报通过。
