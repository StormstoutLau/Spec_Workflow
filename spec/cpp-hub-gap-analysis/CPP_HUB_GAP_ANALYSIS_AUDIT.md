## 0. 审计范围与方法

**范围**: 报告全部断言（§0 声明 12A+4B+7C+3H）+ 报告自身元声明（断言统计表计数）。

**方法**（按框架 §4 B 类三阶段 + 规则 6）:
1. **A 类机械核验**: 16 条引文逐条 grep 源文件，核对引文逐字 + 行号
2. **B 类探针重跑**: B1-B4 按附录 B 登记的 probe 定义重新执行（counting/existence/equivalence）
3. **逻辑链条检查**: claimed_chain 逐步核对，查跳步
4. **元声明复核**: §0 断言统计表计数 vs 实际 grep 标注数

**扫描范围声明（E4 语义）**: 审计覆盖报告内全部断言与源文件引文锚点；源文件内容本身的正确性（如 pilot 引用的 statsmodels 事实）不在本轮范围——报告已声明转引不重验（§6-4）。

## 4. 形态 II 复发模式记录（本报告核心增量）

### 4.1 三实例谱系

形态 II（弱记忆填充：版本号/章节号/数值常量/计数凭印象）在本方法论体系内已**三次独立复发**：

| # | 实例 | 载体 | 形态 II 表现 | 拦截方式 |
|---|------|------|-------------|---------|
| 1 | Phase 7C 调研报告 | Cpp_Hub PHASE7C_RESEARCH | 8 处错误中 6 处为形态 II（ZA "0.20+"/Lütkepohl §7.2.2/fpp2 §8.7/ZA MC −5.83 等版本号·章节号·常量） | 3 agent 全量重查 |
| 2 | ADR-019 复核 pilot | Cpp_Hub ADR019_REVIEW_PILOT | R2 抽检抓到复核报告**自身** 1 处转述引文失准（B1 登记引文系转述非原文） | R2 门禁机械 grep |
| 3 | **本审计报告对象** | Spec_Workflow GAP_ANALYSIS_RESEARCH | §0 统计表计数错（12A→16A）+ A12 行号偏移（L230-241→L239） | 本轮独立 grep 重验 |

### 4.2 复发规律（从三实例归纳）

**规律一：形态 II 偏好"精确-looking"的低语义载荷字段。** 三实例的错误全部落在**版本号、章节号、行号、计数**这类"看起来精确、语义权重低"的字段上——正是框架 §3 自检清单点名的"最高频错误位"（版本号/章节号/数值常量三类）。这类字段因"显得不重要"而逃过深度审查，又因"凭印象可填"而易错。

**规律二：防幻觉机制自身对形态 II 不设防。** 实例 3 最具揭示性——**断言统计表**本身是防幻觉机制（规则 2 统计溯源的载体），但它自己犯了计数幻觉。根因：**统计断言是关于文档自身的元断言，不属于 A 类（无外部 URL 可 grep）**，因此逃过了 A 类"URL+引文当场拦截"机制。框架的拦截网覆盖"对外部事实的断言"，却漏了"对自身内容的计数断言"。

**规律三：形态 II 无法被"要求给链接"拦截，但可被机械枚举拦截。** 三实例的共同教训：凡是**可机械枚举/可 grep 复核**的字段（计数、行号、版本号），必须在产出时即用脚本生成而非凭记忆填写。实例 2 的 R2 门禁、实例 3 的本轮审计，都是靠机械重跑抓到的——**形态 II 的正确拦截层是 E1 机械核验，不是 LLM 自查**。

### 4.3 结构性缺口与建议

| 缺口 | 建议 |
|------|------|
| 断言统计表（元断言）不在 A 类拦截网内 | 规则增补：**§0 统计表的每个计数必须由脚本枚举生成**（如 `grep -c '【A】'`），禁止手填；统计表本身视为需 E1 证据的断言 |
| 行号锚点易偏移 | 沿用 PLAN v1.2 教训：**行号 + 引文双锚定**，行号仅作导航，引文为真值；重构后行号失效以引文重定位 |
| 形态 II 复发无量化跟踪 | M7 数据单列"形态 II 复发计数"指标：按载体（调研报告/复核报告/统计表）× 字段类型（版本/章节/行号/计数）分桶统计，验证"机械枚举拦截"的实际拦截率 |

> **元观察**: 这是"幻觉点清单自身含幻觉"（Discovery 007 核心命题）的**第三次实证**，且首次落在**防幻觉机制的统计载体自身**上。Discovery 007 预言"验证层必须与生成层独立且结构不同"——本轮审计之所以抓到 §0 计数错，正是因为审计端用独立 grep 重数、未采信报告自带的统计表。**命题再次被证实：自查填的统计表不可信，机械重数才可信。**
