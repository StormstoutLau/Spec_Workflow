## 1. 调研目标

**核心问题**（承 P-042 §7.19 三处缺口）：

1. **缺口 A（未决项未一等公民化）**：「判据 / 触发条件 / 当前倾向 / 证据等级」**四元**能否定形为**统一登记块**，使未决项**可枚举、可引用、可复查**，而非散在散文？
2. **缺口 B（无多维度决策矩阵模板）**：「选项 × 维度」矩阵能否**定形为模板**，使多方案选择**不靠随机**（维度 = 成本 / 收益 / 可维护性 / 兼容 / 升级潜力 / 短期 / 长期）？
3. **缺口 C（无迭代收敛停止规则）**：「**净收敛纪律** + **Type-1/2 委派**」能否作为**停止规则**抑制分析瘫痪，且**不引入门禁**（避免为「判断」造机械拦截）？

**边界（先行声明）**：三件**全部**落 **Layer-0（模板 + 纪律）**——本批**不动任何 Layer-1 位点**，**可机械化的仅形态完备性**（四元是否齐全 / 触发条件是否非空 / 引用是否完整），**绝不核「结论是否正确」**（否则重犯 P-042 **A-33**「对账抓不住两实现同错」与 **DR-21**「未成文约束」之病）。

## 3. 缺口现状取证（E1）

【A】A-1: **P-042 §7.19 三处缺口登记原文**（[链接](../project-console/RESEARCH.md)）——缺口 A/B/C 的**问题**与**建议形态**（四元登记块 / 选项×维度矩阵 / 净收敛纪律 + Type-1/2 委派）已列出；但该轮**止于登记**（原文「**本批不实施**」+ 边界「缺口三件的实施须**另立批**」），其**四元要素在仓内只是散点存在**（见 A-4），**无统一定形**。

【A】A-2: **本仓模板系统现状（E1 机械重数）** = `spec/templates/` 现存 **5 个文件**（`RESEARCH_TEMPLATE` / `DESIGN_TEMPLATE` / `IMPLEMENTATION_TEMPLATE` / `CHECKLIST_TEMPLATE` / `ADR_TEMPLATE`），**无决策矩阵模板**；`CODE_WIKI §3.8` 表列 **5 行**，`CODE_WIKI §10` 声明 `declared.templates = 5`（由 **PT-7A** 正则 `(\d+) 个(?:标准)?模板（` 看护 ⇒ **新增模板必须同步「树行 + §3.8 表 + §9 行 + declared」四处**）。四件套模板的 front-matter 形态 = `type: design` + `status: draft`（ADR 模板为 `type: adr` + `status: proposed`）。

【A】A-3: **流程宪法结构（E1）** = `SPEC_PROCESS.md` **v1.4** 的章节序 = 10 步 Spec 流程 → 文档目录结构 → Review 检查清单（含 **RULE-1~6** 正文 + 文末 ```rules``` **机读登记块**）→ 与 ADD 的关系 → 与 ADR 的关系 → 开发日志 → 启动新 feature 的流程 → 规则登记（DC4）；**既无「未决项登记」节，也无「收敛停止规则」节**（三件缺口的形态件在宪法层**完全缺位**）。

【A】A-4: **未决项现存载体与规模（E1 机械重数）** = ① [P-042 假设区](../project-console/RESEARCH.md) **H5 ~ H9（5 条）**；② **正式观察项**（如 P-042 §7.11，含触发条件与载体预判）；③ **登记型决策记录 DR-1 ~ DR-25（25 条）**（[project-console IMPLEMENTATION §6](../project-console/IMPLEMENTATION.md)）；④ **三处缺口候选**（§7.19）；⑤ `PROGRESS` 优先表「**等触发**」组（P-055 落档）。**形态不统一**：部分条目**只有触发条件**、部分**只有当前倾向**、部分**只有判据** ⇒ **四元不齐**，无法机械枚举「当前未决项全表」。

【A】A-5: **社区形态（E3，未核源码，多源二手；承 §7.19 §二）** = 加权决策矩阵类（**MCDA / AHP / ATAM / CBAM**）为「选项 × 维度」提供了成熟骨架，**但本仓无既定模板**；**satisficing**（Simon）提供「够好即停」的停止规则原型；**Bezos Type-1/2 可逆性**提供「按可逆性分派取证成本」的先例（本仓 **Layer-0 / Layer-1 + 可回退点**为其**等价、非同名**物，见 P-042 A-56 ③）；社区侧两大陷阱 = **分析瘫痪**（维度无限扩张）与 **criteria gaming**（指标被优化而非被满足）⇒ **正需缺口 C 的停止规则**。

## 4. 形态裁定（C 类）

【C】C-1: **载体裁定 = 新 P 行 P-058 + 新 feature `spec/iteration-backflow/`** —— 理由：三件产物是**框架级**形态件（模板与流程纪律），**不属于**「项目控制台」（P-042 的设计对象 = 控制台生成器）；寄生 P-042 会制造错误归属（同 P-042 C-29 / C-30 的载体归属先例）；且 P-058 满足 **V1a 机械边界（P 编号 ≥ P-058）**，成为**「立项即登记」首个活实例**。

【C】C-2: **三件形态裁定** —— ① **件 A（四元登记块）** = 定形为**固定四字段块**（判据 / 触发条件 / 当前倾向 / 证据等级），落 **`SPEC_PROCESS` 新增独立节**（权威定义）+ **`RESEARCH_TEMPLATE` 与 `DESIGN_TEMPLATE` 各增一节**引用（就近可用）；② **件 B（决策矩阵模板）** = **新建独立模板文件** `spec/templates/DECISION_MATRIX_TEMPLATE.md`（选项 × 七维度，每格附**证据等级 + 读数日期**，格内含计数/占比须 **= 机械重数**（**R7 同构**））；③ **件 C（净收敛纪律）** = 落 **`SPEC_PROCESS` 同一新节**（纪律条文 + Type-1/2 委派 + 反模式）。

【C】C-3: **纪律落点裁定 = 新增独立节、不新增 RULE 编号** —— 纪律写为**独立节**（不并入 Review 检查清单、**不新增 RULE-7**、**不动**文末 ```rules``` 机读块）⇒ **不触 DC4 命名空间扩权**（[ADR-0007](../../adr/ADR-0007-unified-document-contract.md) 附录 A 的规则登记契约），**无需另立 ADR**。**代价如实登记**：纪律**不在 `rules` 机读块内** ⇒ **机械可见性弱**（无 id / 无失效条件字段 / 无拦截记录位）；若日后需追溯（来源事故 / 失效条件 / 拦截记录），**再走 DC4 扩权另立 ADR**（登记为本批**已知边界**）。

## 5. 对设计的输入

- **件 A 的字段契约**：四元字段名**固定**（判据 / 触发条件 / 当前倾向 / 证据等级），**顺序固定**（便于机械枚举）；「证据等级」沿用 [ASSERTION_EVIDENCE_FRAMEWORK](../../docs/ASSERTION_EVIDENCE_FRAMEWORK.md) 的 **E1~E5**；「触发条件」**须可机械识别**（承 P-042 B15：不可核判据退化为叙述）。
- **件 B 的表结构契约**：表头 = 维度 / 选项；**每格 = 评估（证据等级 E?；读数日期 YYYY-MM-DD）**；**格内出现计数或占比时，须附复算命令**（声明 = 重数，R7 同构）；**必带「收敛出口」**（与件 C 联动：矩阵**不得**无限扩张）。
- **件 C 的条文要素**：净收敛纪律（**每轮须关闭 ≥1 未决项**，或**新开 ≥1 项但必带触发条件**，否则**不予立项**）+ **Type-1/2 委派**（可逆（Type-2）**先做再改、不启动矩阵**；**仅不可逆（Type-1）**要求全维度取证）+ **反模式**（分析瘫痪 / criteria gaming）+ **诚实边界**（**过程性、不可机械拦截**）。
- **落点表**：`SPEC_PROCESS.md`（新节 + `version 1.4 → 1.5` + 修订行）/ 新建 `spec/templates/DECISION_MATRIX_TEMPLATE.md` / `RESEARCH_TEMPLATE.md` + `DESIGN_TEMPLATE.md`（各增一节）；治理同步 = `CODE_WIKI`（树 5→6 + 新 feature 行 + §3.8 + §9 + §10 `declared`/`doc_registry`）+ `PROGRESS`。

## 附录 C：C 类判断复盘 + 假设区

**C 类判断复盘**:

- C-1: **载体裁定 = 新 P 行 P-058 + 新 feature `spec/iteration-backflow/`** —— 产物为框架级形态件（模板与流程纪律），归属不属「项目控制台」；寄生 P-042 制造错误归属（同 C-29 载体归属先例）；并令 P-058 成为 **V1a 立项即登记首个活实例**。
- C-2: **三件形态裁定** —— 件 A 落 `SPEC_PROCESS` 独立节（权威定义）+ 两模板各增一节（就近可用）；件 B 新建独立模板文件（选项 × 七维度 + 证据等级 / 读数日期 + R7 同构）；件 C 与件 A 同节（纪律条文 + Type-1/2 委派 + 反模式）。
- C-3: **纪律落点裁定 = 新增独立节、不新增 RULE 编号** —— 不触 DC4 命名空间扩权（ADR-0007 附录 A）⇒ 无需 ADR；**代价如实登记** = 纪律不在 `rules` 机读块内、机械可见性弱，日后若要 id / 失效条件 / 拦截记录需再走 DC4 扩权。

**假设区**（未实测，待触发）:

- [H1] **净收敛纪律的有效性未实测**——纪律可被**形式化满足**（为凑「关闭一项」而结掉低价值项，或为凑「新开必带触发」而给虚假触发条件）；触发 = 出现一次**形式化凑数**实例，或观察窗 ≥3 批后复核。
- [H2] **七维度矩阵诱发分析瘫痪的风险未实测**——全维度填写的成本可能反而拖延决策；当前缓解 = **Type-1/2 委派**（可逆项**不启动矩阵**）；触发 = 首次真实启用矩阵后评估其耗时与增益。
