## 1. 设计目标

把 [RESEARCH §3~§4](./RESEARCH.md) 的三件缺口，**定形为可直接复用的形态件**，使「调研 → 初步结论 → 再调研 → 裁定」的迭代过程**不再依赖人读散文**：

1. **未决项可枚举**（件 A）：以**固定四元**登记每个未决项（判据 / 触发条件 / 当前倾向 / 证据等级），使「当前未决项全表」可机械枚举与复查。
2. **方案选择不靠随机**（件 B）：以「**选项 × 维度**」矩阵模板承载多方案比较（维度 = 成本 / 收益 / 可维护性 / 兼容 / 升级潜力 / 短期 / 长期），每格附**证据等级 + 读数日期**。
3. **迭代可收敛**（件 C）：以**净收敛纪律** + **Type-1/2 委派**作为**停止规则**，抑制分析瘫痪与 criteria gaming。

**非目标**：**不**为「判断」造门禁、**不**新建工具、**不**触碰任何 Layer-1 位点。

## 3. 设计决策

| # | 决策 | 理由 |
|---|---|---|
| **D1** | **载体 = 本 feature（P-058）**，产物**跨 4 个落点**：`SPEC_PROCESS.md`（件 A 权威定义 + 件 C 条文）/ **新建** `spec/templates/DECISION_MATRIX_TEMPLATE.md`（件 B）/ `RESEARCH_TEMPLATE.md` + `DESIGN_TEMPLATE.md`（件 A 就近可用节） | 产物是**框架级**形态件，不属任何既有 feature（RESEARCH C-1）；落点按「权威定义一两处 + 就近引用多处」分工（I-2） |
| **D2** | **件 A 形态 = 固定四元块**：`判据` / `触发条件` / `当前倾向` / `证据等级`，**字段名与顺序固定**；**两种承载皆合法**——**块形态**（四行 bullet，适用于文档正文）与**表形态**（四列，适用于多条目汇总） | 固定字段名与顺序是**可机械枚举**的前提（RESEARCH A-4 的缺陷正是形态不统一）；两种承载覆盖「正文逐条」与「汇总表」两种真实用法，避免为统一而牺牲可读性 |
| **D3** | **件 B 形态 = 独立模板文件** `spec/templates/DECISION_MATRIX_TEMPLATE.md`：表头 = `维度 × 选项`；**每格 = `评估（证据等级 E?；读数日期 YYYY-MM-DD）`**；**必含三节** = ① 矩阵本体 ② **收敛出口**（结论 + 未决项，与件 C 联动）③ **Type-1/2 判定**（可逆项**不启动矩阵**） | 独立文件使矩阵**可被任何文档引用**（复用性），且不把七维表结构埋进四件套模板；「每格证据等级 + 读数日期」对齐**R7 声明=重数**纪律（格内含计数/占比须附复算命令） |
| **D4** | **件 C 形态 = 纪律条文三件**：① **净收敛纪律**（每轮**关闭 ≥1 未决项**，或**新开 ≥1 项但必带触发条件**，否则**不予立项**）② **Type-1/2 委派**（可逆（Type-2）先做再改、**不启动矩阵**；**仅不可逆（Type-1）**要求全维度取证）③ **反模式 + 诚实边界**（分析瘫痪 / criteria gaming；纪律**过程性、不可机械拦截**） | 停止规则须**同时**给出「何时可停」（净收敛）与「何时不必重取证」（委派），否则纪律退化为「每轮都必须全维度」⇒ 反向诱发分析瘫痪（RESEARCH A-5 陷阱） |
| **D5** | **纪律写为独立节，不新增 RULE 编号、不动 `rules` 机读块** | 不触 **DC4 命名空间扩权**（ADR-0007 附录 A）⇒ **无需 ADR**；代价（机械可见性弱：无 id / 无失效条件 / 无拦截记录位）**如实登记**（RESEARCH C-3） |
| **D6** | **零代码边界**：**不改** `scripts/` 与 `tools/`、**不改**任何校验器、**不新增门禁 / hook / 模板校验** | 承 ADR-0010 Layer-0 + RESEARCH B1/B2；**落地动作 = 文档与模板的写入**，无运行时足迹 |

## 4. 形态规格（接口定义）

### 4.1 件 A：四元登记块

**块形态**（文档正文逐条）：

```markdown
- **U-<n> <未决项标题>**
  - **判据**：<如何判定「已解决」；须可机械核查或明确指向人工裁决点>
  - **触发条件**：<何时重审；**优先可机械识别**（编号边界 / 计数阈值 / 差集非空 / 事件发生）>
  - **当前倾向**：<当前最可能结论或建议（可写「无倾向」）>
  - **证据等级**：E1~E5 或「待核」
```

**表形态**（多条目汇总）：

```markdown
| # | 未决项 | 判据 | 触发条件 | 当前倾向 | 证据等级 |
|---|--------|------|----------|----------|----------|
| U-1 | <标题> | <…> | <…> | <…> | E2 |
```

**硬约束**：① 四元**字段名逐字固定**（判据 / 触发条件 / 当前倾向 / 证据等级）；② **顺序固定**；③ 「触发条件」**不得**写成不可核的叙述（承 P-042 B15）；④ 「证据等级」取值域 = E1~E5 或「待核」，**不得**另造等级。

### 4.2 件 B：决策矩阵模板

**文件**：`spec/templates/DECISION_MATRIX_TEMPLATE.md`（front-matter 合 DC1 七字段 + DC2 词表：`type: design` / `status: draft`，与四件套模板同形）。

**矩阵本体**：

```markdown
| 维度 | 选项 A | 选项 B |
|------|--------|--------|
| 成本 | <评估>（E?；YYYY-MM-DD） | <评估>（E?；YYYY-MM-DD） |
| 收益 | … | … |
| 可维护性 | … | … |
| 兼容 | … | … |
| 升级潜力 | … | … |
| 短期 | … | … |
| 长期 | … | … |
```

**三节必填**：

1. **矩阵本体**（上表；七维度**逐行固定**，选项列按需增删）。
2. **收敛出口**：本轮结论 + 尚未闭合的**未决项**（格式转件 A 四元块）——矩阵**不得**以「还需要更多维度」收尾（反分析瘫痪）。
3. **Type-1/2 判定**：`Type-2（可逆）⇒ 先做再改、不启动矩阵` / `Type-1（不可逆）⇒ 全维度取证`。

**R7 同构条款**：格内出现**计数或占比**时，须**附复算命令**（声明 = 机械重数）；无法复算者**不得**写入格内。

### 4.3 件 C：净收敛纪律（条文）

```markdown
### 净收敛纪律（迭代批的停止规则）

每一轮迭代批（调研 → 初步结论 → 再调研 → 裁定）**须满足其一**，否则**不予立项**：

1. **关闭 ≥1 个未决项**（附判据达成证据）；或
2. **新开 ≥1 个未决项，且必带触发条件**（可机械识别）。

### Type-1 / Type-2 委派

| 类别 | 判据 | 取证要求 |
|------|------|----------|
| **Type-2（可逆）** | 有可回退点 / 无常驻副作用 | **先做再改**，**不启动决策矩阵** |
| **Type-1（不可逆）** | 无回退点 / 变更真值源或契约 | **全维度取证**（决策矩阵） |

### 反模式（须显式避免）

- **分析瘫痪**：维度无限扩张、每轮只新增未决项而不关闭。
- **criteria gaming**：指标被优化而非被满足（四元被填满但结论未推进）。

### 诚实边界

本纪律为**过程性**约定：**不可机械拦截**（无门禁、无校验器）；**可机械化的仅「四元是否齐全 / 触发条件是否非空 / 引用是否完整」**，**绝不核「结论是否正确」**（承 P-042 A-33 / DR-21 教训）。
```

## 5. 替代方案（否决）

| 方案 | 内容 | 否决理由 |
|---|---|---|
| **方案 G** | 四元登记块**只落 `SPEC_PROCESS`**，不扩 `RESEARCH_TEMPLATE` / `DESIGN_TEMPLATE` | 就近可用性差：实际写调研/设计时**无就近骨架**，会各自重新发明形态 ⇒ 回到 RESEARCH A-4 的「形态不统一」原病 |
| **方案 H** | 决策矩阵**并入** `RESEARCH_TEMPLATE` / `DESIGN_TEMPLATE`（不新建文件） | ① 矩阵会被埋在模板内，**其它文档（ADR / PROGRESS / 独立评估）无引用点**；② 七维表体积会挤压模板主线；③ 与「模板 = 一份骨架一类文档」的既有约定冲突 |
| **方案 I** | 净收敛纪律**升格 RULE-7**（入 `rules` 机读块） | 本批否决：DC4 命名空间扩权**须另立 ADR**（成本 > 收益）；纪律的机械化上限本就低（B2）⇒ 登记为「**若日后需追溯 id / 失效条件 / 拦截记录，再走扩权**」（RESEARCH C-3） |
| **方案 J** | 把矩阵做成 **Layer-1 生成器**（从标记机械生成矩阵 / 机械核收敛） | 撞 **I-10**（为「判断」造门禁 = bespoke 启发式）+ 重犯 **A-33**（对账抓不住「两实现同错」）⇒ 与「**有定形 ⇒ 补位点 / 无定形 ⇒ 只立纪律**」判据冲突（status/结论面**无定形**） |

## 6. 不变式（ADD 审计依据）

- **I-1 零代码（Layer-0）**：本 feature **不改** `scripts/` 与 `tools/`、**不改**任何校验器、**不新增**门禁 / hook。
- **I-2 单一权威**：件 A 形态与件 C 条文的**权威定义只在 `SPEC_PROCESS` 新节**；件 B 的**权威定义只在** `DECISION_MATRIX_TEMPLATE.md`；其它位置（两模板 / 治理文档）**只引不复制**（防多处漂移，同 I-10 精神）。
- **I-3 声明 = 重数（R7 同构）**：矩阵格内含计数 / 占比时须可复算（附命令）；残缺者不得入格。
- **I-4 诚实边界**：可机械核的**仅形态完备性**（四元齐全 / 触发条件非空 / 引用完整）；**结论正确性显式留给人工裁决**。
- **I-5 不触 DC4**：**不新增 RULE 编号**、**不动** `SPEC_PROCESS` 文末 ```rules``` 机读块。
- **I-6 触发条件须可机械识别**：四元中「触发条件」与矩阵的「收敛出口」均不得退化为叙述性声称（承 P-042 B15 / DR-20）。

## 7. 错误处理与边界

| 情形 | 处置 |
|---|---|
| 某轮迭代**未满足净收敛**（既未关闭也未新开带触发项） | **不予立项**（人工裁决）；**不设自动阻断**（I-4 / D6） |
| 未决项**只有倾向、无触发条件** | 视为**形态残缺**；登记为待补（不因此阻断任何机械流程） |
| 矩阵格内计数**无法复算** | **不得写入**格内（I-3）；改写为定性评估或补复算命令 |
| 纪律被**形式化满足**（凑数） | 属**已知盲区**（RESEARCH [H1]）——触发 = 出现一次实例或观察窗 ≥3 批后复核 |

## 8. 职责边界

- 本 feature **不拥有** `SPEC_PROCESS.md`：本批**提交修订**（新增节 + 版本 1.4 → 1.5），权威源仍为 `SPEC_PROCESS`。
- 本 feature **不拥有** P-042：仅**承其 §7.19** 三处缺口（触发条件① 兑现），**不回改** P-042 正文（其「本批不实施」为**当时**的准确记述）。
- 本 feature **不引入**任何工具、门禁、校验器或新依赖。
