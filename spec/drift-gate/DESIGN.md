## 1. 设计目标

把 SGE 的「意图图 vs 证据图双图校验」思想，以**概念登记**形态纳入本仓候选池——作为 repo_stats 的演进候选（关联 pattern_lib_version 2 候选议程）。目标约束 = **零实现、零依赖、零校验器改动、仅登记**（Layer-0 概念吸收，ADR-0010 纪律）。本设计同时**以自身为被测对象执行懒加载 gate 三问**（吃狗粮，同 P-020/P-021 先例）。

## 1.1 收益分析

| 项 | 收益 | 性质 |
|----|------|------|
| 对账语义升级登记 | repo_stats 从「声明=重数」单向对账，登记「意图→证据→缺口」闭环演进候选（区别：Bool 对账 → 缺口定位报告） | 方法论加强（低/登记级） |
| 思想留、工具拒 | 吸收 SGE 双图校验思想（Layer-0），不引入其运行时/图数据库/实现——「工具可拒、思想可留」先例（同 ADR 三层/Ponytail 概念族） | 分层吸收（CER Q1 预演，Layer-0） |
| 触发驱动 | 作为 pattern_lib_version 2 候选**仅登记**，无触发不实施——不排队、不膨胀（ADR-0010 Q2/Q3） | 懒加载纪律再实证 |

## 3. 架构设计

### 3.1 整体架构

```

        │  仅登记（精神吸收，Layer-0）
        ▼
repo_stats 演进候选 = 「意图（声明）→ 证据（重数）→ 缺口报告」闭环
        │  激活条件 = pattern_lib_version 2 候选议程触发（当前不触发）
        ▼
（未来 DESIGN，本批不实施）
```

## 4. 懒加载审核（ADR-0010 三问门禁——正式执行）

> 依据 [ADR-0010](../../adr/ADR-0010-lazy-loading-architecture-gate.md) 三问门禁，以本 feature 的候选吸收物（drift-gate 概念登记）为审理对象逐问作答。CER v1.3 已做 Q1 预演（Layer-0），本设计为该预演的正式审核记录。

| 问 | 审理 | 结论 |
|----|------|------|
| **Q1 放哪层** | drift-gate 概念吸收 = 纯方法论思想登记（无运行时、无文件产出、无激活管线），满足 Layer-0 定义（文档层；纯文档消费者零工具依赖即可使用）。它不是工具/服务，不依赖任何运行时。 | **Layer-0**（与 CER v1.3 §3.4 预演一致）|
| **Q2 激活条件** | 无独立激活——登记即存在。其「repo_stats 演进」的激活触发器 = **pattern_lib_version 2 候选议程**（P-014 立），CER §3.4.1「下一步 = 无（仅登记）」。当前不触发，不排队、不实现。 | **触发驱动（无当前触发）**|
| **Q3 未激活副作用** | 未登记该概念 = 无任何足迹（不 import / 不扫描 / 不改 repo_stats / 文档层无感知——零实现 I-1 保证唯一产出 = 本两件套文档本身，属 Layer-0 文档成本）。repo_stats 演进未激活 = 现状对账行为完全不变（三通道无差异）。副作用 = **0**。 | **0** |

**审核结论：通过。** drift-gate 概念吸收是 Layer-0 候选的教科书实例（同 AGENTS.md 桥）——三问全部满足：Q1 Layer-0、Q2 触发驱动、Q3 副作用 0。与 CER §3.4 矩阵「分层归属 = Layer-0（概念吸收，仅登记 repo_stats 演进候选）」一致，验证 `pattern_lib_version 2` 关联成立。

**加注（吃狗粮观测）**：本 feature 全部交付 = 两件套文档 + 登记，无任何工具/依赖改动——**它自身就演示了「Layer-0 概念吸收如何零副作用地纳入候选池」**，是懒加载原则的又一次自我实证。

## 5. 替代方案

### 5.1 方案 A：概念登记（选择）
- 描述：把 SGE 双图校验思想登记为 repo_stats 演进候选，零实现。
- 优点：贴合 CAR「工具可拒、思想可留」；零成本；懒加载纪律自证。
- 缺点：无即时机械收益（仅登记）。
- 选择理由：CER §3.4.1「仅登记」建议 + ADR-0010 Layer-0 优先；用户指定走到懒加载 gate。

### 5.2 方案 B：实现 repo_stats 缺口报告（否决）
- 描述：本批实现「意图→证据→缺口」闭环。
- 优点：机械收益立现。
- 缺点：违反用户「运行到懒加载 gate 部分即可」边界；未过激活触发器（pattern_lib_version 2 未触发）；一次性膨胀。
- 否决理由：ADR-0010 触发驱动 + 用户边界声明确立。

### 5.3 方案 C：引用 SGE 图数据库实现（否决）
- 描述：引入 SGE 式意图图/证据图运行时。
- 优点：对齐原论文完整。
- 缺点：重依赖违反零依赖 D6；本仓无图数据库规模需求；YAGNI。
- 否决理由：D6 零依赖 + ADR-0010 连锁否决（Proxied 重依赖候选，如 Langfuse 先例）。

### 9.2 实施内容（repo_stats.py，最小 diff）

- `CheckResult` 增可选 `gap: str | None` 字段（dataclass 尾部，既有构造全兼容）——缺口三元组载体。
- 4 处填充点：`rs-decl`（声明 vs 重数 ±差 + 欠/过声明）、`§2.1 树缺登/幻影`、`§9 索引缺行/幻影`、`doc_registry 版本失配`——均以「意图(…) → 证据(…) → 缺口 …」形态捕获。
- `_gap_report(results)`：提取带 gap 结果 → `[gap-report]` 块（明细 + 载体分布）；无缺口返回空串。
- `main` 门控：`pattern_lib_version >= 2` 时自动输出 gap-report（无缺口则静默）。
- `pattern_lib_version` 默认保持 1（selftest 迷你仓不激活）；真实仓 CODE_WIKI §10 stats 块 **1 → 2** 激活。
- 退出码语义不变：P1/P2 → 1（缺口=阻断），P3 → 0（提示）——「是否该阻塞」沿用验证层级（缺口定性于缺口报告内）。
